Tricast Sweep — Locality Behavior Over 90 min

Data source. DONE lines in worker-*-worker.log across the three snap-XXX windows. Each snap covers 30 min; workMs classifies the DONE as warm (~2 s) or cold (≥ 10 000 ms → either Small 45 s or Large 180 s).
Four charts per bench:
  1. Throughput (jobs/min per 30-min window) — dashed line = target rpm. Curve dropping below target = fleet is queue-bound.
  2. Cold-rate (% of DONE in window with workMs ≥ 10 s) — measures how much of the workload is paying the cold-tax. Locality should collapse this to 0 after the first window.
  3. Active pods (# distinct pods with any DONE in the window) — fleet footprint. Baseline spreads work across all pods; locality concentrates it on a small canonical set.
  4. Label footprint (# distinct pods that ever hosted each label over the full 90 min) — per label, how many pods did we have to warm up? Baseline ≈ P (full fleet warmed); locality << P (only picks stay warm).
