Production Locality Waste — Top 3 Windows Regions

Question. The bench report shows a 90× P99 latency improvement and a 5-10× fleet-footprint reduction from locality routing. This report answers: in production, why are so many encryptions "wasted"? For a given hot region, how many distinct images are being downloaded, at what rate, and to how many nodes?

Data source. Kusto MdmMetrics table on azsectvmcvm.centralus/CVM, metric WindowsEncryptionNumberOfRequests, dimension dv[0]=ImageReference, dv[1]=ImageSource, dv[4]=Node. Long-form rows only (array_length(dv) == 8); each row is one encryption request. Window = last 7 days, 2h bins for time-series.

Waste model. If a single label (image) is downloaded & encrypted on Nodes distinct nodes but the actual distinct request rate would fit on ideal=2 nodes (bench-observed 1 warm pod + 1 HA replica), wasted = Requests * (1 - ideal/Nodes). Each wasted encryption is roughly a full ~45 s (small) or ~180 s (large) cold download+decrypt+re-encrypt.

Headline finding. Every top image in every region touches essentially the entire fleet (spread 98-100%), even though its actual request rate is only 1–25 requests/hour. In every 2-hour window the same image is dispatched to >90% of nodes — each of which pays a full cold-download tax the very first time and rewarms whenever the L1 evicts. The bench measured that with locality routing this footprint collapses to 1–2 pods per image (+1 HA replica) with zero cold-tax after the first minute. Applying ideal=2 across the three regions eliminates 83,199 of the 86,094 weekly requests — a 29.7× reduction in redundant cold encryptions.

Cross-reference to the bench report

The tricast bench sweep ran nine scenarios (rpm × N labels × P pods) with three topologies: baseline (Kubernetes default), central (single warm pod per label + HA replica), pernode (label-affinity DaemonSet). Baseline reproduces production behavior — full-fleet spread per label, high cold-tax, P99 pinned at the cold-copy time. Central and pernode both converge to 1–2 pods per label, cold-tax = 0 after the first window, P99 = warm floor (~2 s).

The production 100%-fleet-spread observed above is the same pattern the bench exhibits under baseline. Every top image in usw3/bl/am has been observed on every node in the fleet within a 7-day window. The bench validates that ideal=2 is not aspirational — it is exactly what pernode & central topologies converge to across all nine scenarios.
